## 2026-09-20 requirement audit and design pass

A nine-dimension audit re-read the 2026-09-19 requirements against the code and adversarially verified every finding (23 confirmed, 3 refuted). What it changed:

**Requirement defects fixed.** A press near a cell's top/left edge began a row/column reorder, so press-and-release on the same cell rebuilt the whole table, replaced the cell selection with a text selection and burned an undo step — the drag-to-select requirement was unusable in that 6px band. `moveTable` now treats a reorder that ends on its origin row/column as a click. Inserting or deleting a table row/column wrote a literal `<br />` into the user's Markdown because Milkdown's `remarkPreserveEmptyLine` serializer replaces empty paragraphs with it; both halves of that remark are now filtered out of the commonmark preset, so an empty cell serializes as an empty cell. A second window's stale settings snapshot overwrote the shared record: `save_settings` now takes a key patch, `settings::merge_patch` applies it to the held record, and the store sends only the keys it actually changed (recent history stays server-owned). Mermaid's "hide the diagram while its source is open" guard keyed off a Vditor DOM class that Milkdown never renders; it is now a node-view `editing` hook, so a theme change can no longer cover an open source editor.

**Sidebar and help.** Creating a file or folder was right-click-only once the bottom action bar was removed; `workspace.create` plus `file.newFile` / `file.newFolder` registry commands give the command palette, the shortcut panel and a re-mappable shortcut the same path. The shortcut-help panel promised function search but silently dropped every command without a shortcut; it now lists them under 无快捷键 while searching, and the footer explains that Mod means ⌘ / Ctrl. Shortcut search normalises both sides, so `cmd s`, `ctrl+shift+p` and `⌘S` all reach `Mod+S`.

**Design pass (redesign-existing-projects).** Design tokens replace scattered literals: one type scale, the 4/6/10/12px radius scale, three theme-aware tinted shadows, two backdrops, one transition, and a named ladder for the modal layer (the remaining overlay z-indexes are still literals; the `--y-z-chrome/float/menu/popover` names exist but are not yet applied). Modal titles share a single size (they were 16/17/18px for one role); the AI panel and the shortcut panel now share one header and body shell; `.settings-body nav` is scoped to its direct child, removing two `!important` workarounds that the AI category tabs needed; editor headings are a real scale again (H3 and H4 were the same size, H5/H6 smaller than body text); blockquote rules and inline links use theme tokens instead of near-white and hard-coded blue; the document "more actions" menu sizes to its labels instead of the shared fixed width, which left roughly half of every row empty; the file tree, AI history and settings tables have empty states; word count, palette count and usage readouts use tabular numerals. Overlays that live outside the app shell (editor context menus, the table picker, the diagram presentation dialog) are detached from their ancestor, so they now copy every `--y-*` property onto themselves — otherwise the new radius, shadow and backdrop tokens would resolve to nothing there.

**Deletions.** About 150 lines of CSS that could not match any rendered element: `.vditor-ir__node`, `.vditor-ir__node--expand`, `.vditor-ir__marker--pre`, `.vditor-ir__preview`, `.vditor-ir__marker--heading`, `.vditor-sv`, `.vditor-content`, `.vditor-toolbar`, `.editor-host.vditor`, the `.focus-mode`/`.typewriter-mode` blocks, the highlight.js token colours, and the two `.vditor-ir > .vditor-reset` prose blocks. The last of those is worth spelling out: the real ancestry is `.milkdown-preview.vditor-ir > .milkdown > .ProseMirror.milkdown-document.vditor-reset`, so a *direct child* match on `.vditor-ir > .vditor-reset` never held — the editor's font, padding and scroll container all come from `.editor-host .milkdown-document` in desktop.css. Also removed: the unreachable native drag handlers in `interactions.ts`, the Vditor-DOM fallbacks in `mermaid.ts`, `src/editor/adapter/vditor-patches/`, the empty `patches/`, and the unused `highlight.js` dependency. The descendant-form `.vditor-reset` / `.vditor-ir` compatibility classes stay: they carry user-imported Typora CSS and the shared interaction helpers.

Verification: 59 frontend tests across 13 files and 19 Rust tests pass, with `pnpm lint`, `pnpm typecheck`, `pnpm build`, `cargo fmt --check`, `cargo clippy -D warnings` and `cargo test` all clean on macOS ARM64. New tests fail without their fix: the edge-press case, the empty-cell serialization, the shortcut-spelling search and the settings patch merge. Native multi-window click-through, OS dialogs, keychain prompts and Windows runtime still require an unlocked host and are not certified by these tests.

Known limitations after this pass, recorded rather than hidden:

- **No cross-window settings broadcast.** A save updates the shared SQLite record, but other windows keep their own snapshot until reload, so a window can display a provider label that no longer matches the record the AI process actually starts from. Only the changed keys are written, so no window's edits are lost. A `settings-changed` event plus a merge that prefers a window's unsaved local keys is the intended follow-up.
- **`providerProfiles` and `shortcuts` merge at the whole-array level.** If two windows both edit those two fields before either saves, the later save wins for the whole array. Every other key is merged individually.
- **Table rows of unequal width are not normalised.** Markdown tables are parsed rectangular, so `rowsOf` keeps its current assumption; a hand-crafted ragged table could still throw inside a column operation.
- **`--y-row-height` is read by the file-tree virtualiser and applied as `min-height` on `.tree-item`.** A user theme that restyles row padding could still move the rendered height away from the value the virtualiser measured at mount.

## 2026-09-21 table, Mermaid, AI panel and UI framework

Triage first: five parallel diagnoses with an adversarial re-check found 11 real defects behind the new requirements (16 further items were design proposals, 1 was refuted). What shipped:

**Tables.** A right-click (or macOS ctrl+click) on a live multi-cell selection destroyed it: with `button !== 0` the handler returned before `preventDefault`, the browser moved the DOM caret, ProseMirror read it back as a `TextSelection`, and the menu could no longer act on the selection. It now suppresses the default while a `CellSelection` is live. Rows and columns could only be dragged from an invisible 6px border band — the header row is now the column handle, the cell's left edge stays the row handle, and both got a cursor hint. A press released on its own row or column is still a click, not a reorder, so a plain header click leaves the table alone; text editing in a header still starts with a double-click, which the press handler ignores. Remaining native `<select>` elements (font family, resource filters, the AI connection row, the provider transport) are listed as pending in the task card. Right-clicking a cell opens the menu with the 表格 submenu already expanded.

**Mermaid.** The 完成编辑 button is gone; the editor exits when you press anywhere outside the block, and `Escape` and `Mod-Enter` also exit — removing the button without those two would have stranded keyboard users. The exit listener must be on the capture phase and test containment against the whole `.y-code-block`, because the render host isolates pointer events by stopping propagation and `.mermaid-render` is hidden while editing. Mermaid source is now highlighted: `@codemirror/language-data` has no Mermaid entry, and `codemirror-lang-mermaid` bundles every diagram parser into one module, so it is imported dynamically only when a diagram exists.

**AI panel.** The composer was a dead input: `:disabled` was bound to a persisted `ai.enabled` flag that defaults to false and that the panel itself could not turn on. The composer is always usable now, the send button gates on `ai.busy || !prompt.trim()`, and choosing a connection in the panel is the act of enabling it. The upload button is gone per the requirement, so `@` gained an image path — listed panel-locally (never by flipping the sidebar's `allFiles`) and read through the existing `image_read`, with no new Rust command. The connection picker gained ＋ 新增连接… opening Preferences directly, and a model typed in the panel is written back to its profile instead of being silently reverted on the next connection switch. The `@`/`/` popup no longer collapses into one cramped row: `.ai-input > div` outranked `.ai-suggestions` and leaked a flex row onto it.

**UI framework (ADR-0007).** Tailwind 4 and shadcn-vue are in. Tailwind is imported in layers with **preflight disabled** — it resets list markers, blockifies inline images and rewrites borders, all of which the Markdown surface gets from user-agent defaults this project never declared. `@theme inline` over the `--y-*` names keeps the eight presets the single source of truth, `--y-accent` maps to `--primary` (shadcn's `--accent` is the hover surface), the tokens moved to `:root` and the colours are mirrored onto `documentElement` so portalled overlays resolve them, and the dark variant follows the app's resolved appearance rather than the OS preference. Copied components are ours: `SelectContent` lost its animation classes (no `tw-animate-css` for motion this product does not want) and its `z-50` became the `--y-z-modal-top` token, because `z-50` sits below the modal shade. First migrated control: the preset and appearance selects, asserted by `tests/settings-select.test.ts`.

**macOS pass.** Real traffic lights replace the drawn `− □ ×` cluster and the in-window menu bar is now the browser preview's stand-in only (`decorations: true` + `titleBarStyle: Overlay` + `trafficLightPosition`, in both `tauri.conf.json` and the new-window builder). The icon system is one drawn set — Lucide at 1.75 stroke — replacing every Unicode stand-in (⋯ ☷ ↻ ⛶ B I S ↗ × and the ☐/☑ task glyphs, which were also dead code: Milkdown renders a real checkbox inside `.task-list-item` and never sets `data-checked`, so the pseudo-element drew a second marker). The status bar had four disagreeing definitions (26/42/28px bars with 36px and 18px controls); there is one now, on `--y-control-h-sm`. The focus ring is one definition (transparent outline + accent halo, so Windows High Contrast still gets a border). Scrollbars, text selection and placeholders are themed from the palette. List selection follows the AppKit rule — accent when the window is key, neutral when it is not. Code uses the system mono stack. Error red and accent ink are tokens, and `--y-accent-ink` is computed per preset from the accent's luminance because white on `#4183c4` is only 4.00:1.

Verification: 15 files / 70 tests and 19 Rust tests pass, with lint, typecheck, build, `cargo fmt --check` and `cargo clippy -D warnings` clean. Every new test was checked to fail without its fix. **Not verified:** no visual pass ran — `tauri-driver` reports "not supported on this platform" on macOS, so the traffic-light geometry, the portal z-order, the overlay scrollbars and the overall macOS read still need one look on an unlocked host.
